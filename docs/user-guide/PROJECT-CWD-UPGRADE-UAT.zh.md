# Projects/CWD 统一升级用户验收用例

适用版本：`1.7.91`。本清单验证 Agent 左栏改为项目树驱动，以及
`projects.path` 成为已绑定会话实际工作目录后的升级行为。

## 验收目标

- 可见的 `workspace` 项目是左栏根节点，即使暂时没有会话。
- 已绑定会话只归属到其 `project_id` 对应的项目；运行、重开、文件读写和图片落盘都使用 `projects.path`。
- `cwd` 仅保留为旧数据、未归属会话和无效绑定的兼容回退，不能再生成普通项目根节点。
- IM 自动会话保持在 `IM会话`；其他不可见内部项目或旧会话保持可访问，但不会伪造成普通项目。
- 首次升级不能丢失历史会话、消息、项目名称或用户后续的显示偏好。

## 测试准备

1. 使用独立测试配置目录，或在升级前备份现有的用户数据目录和 `sessions.db`。迁移用例必须基于有历史项目和会话的数据，不能用空数据库代替。
2. 创建三个真实目录：`UAT-Alpha`、`UAT-Beta`、`UAT-Empty`。在 Alpha、Beta 中各放入一个容易识别的文本文件。
3. 准备一张图片和一个 PDF 或 Office 文件。文件名应至少覆盖中文、空格和 `#`。
4. 如需覆盖 IM 用例，准备一个可收发消息的测试联系人或群，并确认对应桥接已启用。
5. 每项记录：用例编号、系统、构建版本、测试配置目录、实际结果、截图，以及发生异常时的主进程日志。

## P0：升级、项目树和运行目录

### UAT-01 首次升级与重复启动

前置：旧版本数据中至少有两个普通工作区项目、一个关闭会话和一个活动会话；如已设置项目置顶或折叠，也应保留该状态。

步骤：升级到目标版本并首次启动，确认左栏后退出应用并再次启动。

预期：

- 应用正常进入主界面，不出现白屏、数据库迁移错误或要求重建数据的提示。
- 已知项目和会话均可找到并打开，历史消息仍可阅读。
- 第二次启动不重复迁移，不新增重复项目根节点，也不回退用户在首次启动后的名称、排序、置顶或展开选择。

### UAT-02 可见项目根节点和空项目

步骤：分别通过“新建对话”的文件夹选择器选择 Alpha、Beta、Empty，确保三者成为工作区项目；删除或关闭 Empty 下唯一的测试会话，然后刷新左栏或重启应用。

预期：

- Alpha、Beta、Empty 都以独立项目根节点出现；Empty 没有会话时仍必须显示。
- 每个会话只出现在一个项目下，不会按旧 `cwd` 再生成同名或同路径根节点。
- 选择文件夹后，该项目会出现在“最近项目”中；再次新建时选择最近项目会继续在同一项目下创建会话。

### UAT-03 已绑定会话的实际工作目录

步骤：在 Alpha 项目下新建会话，要求 Agent 创建 `uat-bound.txt` 并读取 Alpha 中预置文件；再粘贴一张图片并发送。

预期：

- `uat-bound.txt` 位于 Alpha，不得出现在 Beta、默认输出目录或旧 cwd。
- 粘贴图片保存在 Alpha 的会话图片目录中，Agent 能引用该文件；不应落入其他项目。
- 左栏中该会话仍只挂在 Alpha 下。

### UAT-04 重开、清空重建和恢复

步骤：在 Alpha 下的非 IM、非 Notebook、非嵌入应用会话中，关闭后从左栏重新打开并继续对话；在普通 Agent 聊天输入框中输入本地命令 `/clear`（没有独立按钮），随后在新会话发送一条消息并创建一个文件。

预期：

- 重开和 `/clear` 创建的新会话都保留 Alpha 项目归属。
- 新文件仍写入 Alpha；`/clear` 前的会话软关闭并保留为历史记录，不会移动到未归属会话。
- 重新启动应用后，新的会话仍出现在 Alpha 下。

### UAT-05 已绑定工作区目录丢失

步骤：关闭应用，将 Alpha 临时改名为 `UAT-Alpha-moved`，启动应用并向 Alpha 的历史会话发送消息或图片；测试结束后恢复原目录名。

预期：

- 产品明确报告项目目录不存在，并在创建 Agent 运行、写入图片或文件之前停止。
- 不得在原路径静默创建一个空目录，不得退回到历史 cwd，也不得把会话改挂到 Beta 或未归属会话。

### UAT-06 项目显示名称重命名

步骤：右键 Alpha 项目根节点，重命名为“验收 Alpha”；重启应用，并从“新建对话”的最近项目列表选择它。

预期：

- 左栏根节点和最近项目列表均显示“验收 Alpha”。
- 磁盘目录仍为 `UAT-Alpha`，其中的既有文件和会话不受影响。
- 空名称不能保存；未归属会话、IM会话和内部项目没有项目重命名入口。

### UAT-07 旧的未归属会话

前置：升级前存在仅有 cwd、未能匹配到保留项目的手工历史会话。若没有这类数据，应从旧版测试配置目录导入，不要伪造普通项目来替代。

步骤：升级并打开该历史会话，继续发送一条普通文本消息。

预期：

- 会话显示在“未归属会话”，而非以 cwd 最后一级目录名生成新的普通项目根节点。
- 历史仍可打开和继续使用，并继续使用自身兼容 cwd。
- 未归属分组不可作为项目重命名或项目排序对象。

### UAT-08 项目树偏好和筛选

步骤：置顶 Alpha、将 Beta 折叠、调整两个普通项目的顺序；重启应用。随后依次使用目录筛选和来源筛选，选择 Alpha、全部目录和一个已启用的来源。

预期：

- 置顶、顺序和展开状态在重启后保留；从旧版升级时，已有 cwd 维度的偏好应迁移到对应项目而非丢失。
- 目录筛选只显示目标项目会话；取消筛选后恢复完整项目树。
- 来源筛选只影响可见会话，不能把会话移动到错误项目，也不能把 IM 会话混入普通项目树。

## P1：自动会话、IM 和内部工作区

### UAT-09 IM 会话分类和持续归属

前置：对每个已启用通道分别执行：飞书、钉钉、企业微信；个人微信按已启用能力执行。

步骤：从同一 IM 联系人或群连续发送两条文本消息，再从不同联系人或群发送一条消息；随后在第一个目标中依次发送 `/close`、`/new` 和一条普通文本。需要恢复历史时，发送 `/resume` 并按返回菜单选择编号。

预期：

- 外部 IM 发起的自动会话显示在 `IM会话`，不生成普通项目根节点。
- 同一联系人或群复用正确会话；不同目标不串会话。
- `/close` 后不会静默串到其他已激活会话；`/new` 为当前联系人或群创建并激活新会话，`/resume` 只恢复所选历史会话。
- IM 会话可以正常打开、继续回复和重启后恢复；项目树中的 Alpha、Beta 不受影响。IM 端不使用 `/clear`。

### UAT-10 IM 入站附件的落盘目录

步骤：从每个已启用 IM 通道向测试会话发送图片和准备好的文档，再要求 Agent 读取或总结该文档。

预期：

- 附件在该 IM 会话的有效目录下保存，文档通常位于 `im_attachments/`；不能写进另一个项目或另一个 IM 会话。
- Agent 能看到本地文件路径并处理文件；含中文、空格或 `#` 的文件名仍可用。
- 同一 IM 会话的后续附件不会意外覆盖或混入其他会话。

### UAT-11 会话应用和定时任务

步骤：启动一个会话应用；创建并手动执行一个定时任务。若两者可指定项目，分别选择 Alpha 和 Beta。

预期：

- 会话应用和定时任务会话保持可访问，带有对应的应用或定时任务标识。
- 它们绝不进入 `IM会话`。绑定了可见项目时出现在该项目下；使用内部自动目录时可位于“未归属会话”，但不能伪造新的普通项目根节点。
- 各自产生的文件位于各自有效目录，不能写入无关项目。

### UAT-12 Notebook 和嵌入应用

步骤：打开一个 Notebook 或嵌入应用，完成一次普通交互；若产品提供“打开工作目录”，确认其目录可用。

预期：

- 交互、重开和文件操作正常，不因项目迁移导致启动失败。
- 内部目录不会作为用户可见工作区项目被错误显示、重命名或与 Alpha/Beta 合并。

### UAT-13 内部目录冲突

前置：由测试人员提供一个已被 Notebook、嵌入应用或自动输出会话占用的内部目录。

步骤：在“新建对话”中尝试将该目录作为普通工作区选择。

预期：

- 产品报告目录身份冲突，不能把内部项目提升为可见 `workspace`。
- 原内部会话和文件保持可用，没有被隐藏、迁移或改名。

## macOS 专项

### UAT-14 APFS 大小写规范化

前置：在默认大小写不敏感 APFS 上，准备一个真实目录 `.../UAT-MacCase`，以及旧数据中仅大小写不同的该目录项目记录。此用例通常需要从旧版本测试配置目录升级或由工程人员提供测试数据。

步骤：升级后，通过文件夹选择器再次选择该真实目录并创建会话；重启后再检查左栏和最近项目。

预期：

- 左栏和最近项目中只有一个该目录项目，不能因大小写差异创建第二行项目记录或第二个根节点。
- 新旧会话都能打开，运行目录和文件落盘都指向同一个真实目录。

### UAT-15 macOS 嵌入应用路径

步骤：在 macOS 打开一个嵌入应用并执行一次交互，随后回到 Agent 左栏。

预期：

- 应用工作区识别使用 POSIX 路径层级，功能正常。
- 嵌入应用工作区不会因 `/` 与 Windows 分隔符差异被误判为普通工作区项目。

## 通过标准和缺陷记录

- UAT-01 至 UAT-08 全部通过，才可判定项目/cwd 主链路可发布。
- UAT-09 至 UAT-13 对当前启用的通道和产品模块必须通过；未配置的通道记录为“不适用”，不能记录为通过。
- macOS 发布必须完成 UAT-14、UAT-15；Windows 发布至少完成 UAT-01 至 UAT-13。
- 以下任一现象为阻断缺陷：启动迁移失败或白屏、历史会话/消息丢失、同一目录出现重复普通项目、已绑定会话在错误目录运行或写文件、IM 会话进入普通项目树、目录缺失时静默创建或写入其他目录。
